## Bugs found
1. **Agency demo data served under the daycare** - `daycare_growth.py:152` `eco_overview()` has no `_is_demo_account` guard (unlike `ads_overview` at `:90` and `social_overview` at `:134`). Live `/api/daycare/eco` returns account "Bloom Dental", "Gentle dentistry for the whole family", ROAS 10.26. The Growth UI only reads `context`/`dataSource`, so nothing is painted today, but the Telegram partner (`api_get`) and any future UI can read it, and `/eco/ideas` falls back to this same payload (`daycare_growth.py:167-`, template fallback at its `except`/no-key branches). Fix: apply the same demo-account guard in `eco_overview` and return `{configured:false, best:[], weak:[], next:[]}`.
2. **False-ready indicators.**
   a. `daycare_ads_studio.py:109-119` `meta_ready()` = token present, so `/nova/status.metaReady=true` while Meta rejects the token; the "Build in Meta" button stays enabled (`daycare_growth.jsx` passes `metaReady`). Fix: `meta_ready()` should also require `agency_ads.connection().source != "auth_error"` under the daycare scoped env.
   b. `daycare_director.py:1002` `aiReady = bool(key)` and `daycare_director.jsx:70` renders "Scoring: Claude / live model" in green while `forge_heartbeat.ai_health` is hard-down (credits). Fix: AND with `not forge_heartbeat.ai_health().hard`.
3. **Director page hides most of the brief** - `daycare_director.jsx:95-110` renders only priorities, enrollment, money ("Growth economics"), people ("Capacity to enroll"), delegations. `roster` (Seats), `followUps` (Keep + refer), `campaignHealth`, `competitorRead`, `creativeRecommendations` are in the payload but never shown, contradicting CLAUDE.md section 10 ("UI labels ... Seats / Keep + refer") and `agents/daycare/solomon.md`. Fix: add `<DdrList>` blocks for those keys (competitorRead is an object).
4. **Replies lane retries the same threads forever during an AI outage** - `daycare_replies.py:440-466`: each 60 s sweep re-attempts the same 3 threads and makes one doomed Claude call (connector.err.log: 364 + 200 + 180 repeats per thread; heartbeat errStreak 1,770). Harmless in cost but it keeps the loop red and floods the log. Fix: at sweep start, return early when `forge_heartbeat` reports the AI hard-down (re-check every ~15 min).
5. **Solomon shows a stale brief as current** - `/director/overview` serves the 2026-08-01 brief (before the 2026-09-30 growth-only rewrite; `failStreak` 37). UI labels it by date only. Fix: show a "stale - N days old" badge when `lastBriefAt` > 48 h, or hide it when older than `GROWTH_SINCE`.
6. **Migration folder drift** - `forge-daycare/supabase/migrations` has 34 files; the daycare app's folder has 63 (29 missing, e.g. blessings_pass follow-ups, stripe_tuition_payments, timesheets_pickup_approval, center_closures, web_push, parent_alerts). CLAUDE.md section 10 says "9 newer migrations" (now stale). Also the live DB's migration log lacks those 2026-09-27..29 names even though their tables exist (applied outside the tracked path). Not user-visible; matters for any future rebuild.
7. **Docs drift (minor)** - `agents/daycare/solomon.md` says Replies tick 300 s (code/live: 60 s) and "no other on/off knob" for the brief (there is `FORGE_SOLOMON_BRIEF`, `daycare_director.py:80`); `daycare_director.jsx` hero says "30-year director" vs 50-year everywhere else.
8. **Column-grant 403 class: no live instance found.** All `select: "*"` sites in `daycare_supabase.py` target classrooms, staff_shifts, announcements, notifications, attendance, locations, reward_items, pass_*, invoices, children - none on `profiles` or `staff_members`; those use `_STAFF_COLS`/`_PROFILE_COLS` (`:1042-1043`), `staff_pay_rates` RPC and `guardian_contacts` RPC. Every daycare GET returned 200 at all 3 centers. One note: `_ensure_location_record` (`:1066-1078`) falls to `"*"` for any table other than staff_members - safe today (callers: children, classrooms, invoices, message_threads, announcements, pass_*, reward_items, staff_members) but a future call with `"profiles"` would 403.
