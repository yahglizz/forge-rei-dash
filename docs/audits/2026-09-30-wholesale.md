## 3. Bugs found

1. **Scout hides AI failure, `last_error` wiped** - `scout_triage.py:519` sets `self.last_error = "claude: ..."` when the scoring batch fails, then `scout_triage.py:742` (`self.last_error = None` at the end of the same `poll_once`) overwrites it. Result: `/api/scout/summary` `lastError:null`; `aiScoring` (`:945,:986`) is just `bool(key)`. Operator sees "AI scoring: on" while every new lead is rule-scored. Fix: only clear `last_error` if `claude_out` is non-empty or nothing was sent to Claude; expose `forge_heartbeat.ai_health()` in `aiScoring`.
2. **Analytics counts every conversation 4x** - `analytics_engine.py:40-63` pages with `startAfter`/`startAfterId`, which GHL ignores, so 4 pages return the same 100 convs. Proof: `days=30` scope 8, `days=60` scope 40, `days=120` scope 400 - always multiples of 4 and exactly 4x the 2/10/100 conversations in the newest-100 list. Unanswered, inbound-last, byHour/byDow, classification and Marcus stats are all inflated 4x. The weekly-review agent consumes the same bundle. Fix: use Scout's `sortBy=last_message_date&sort=desc` + `startAfterDate` cursor and dedupe by `id` (as `scout_triage._fetch_conversations` does).
3. **Analytics empty window falls back to all-time** - `analytics_engine.py:134` `scope = in_window or convos`: `days=7` (no activity) reports 400 convs/112 "unanswered" as if recent. Fix: return empty scope with a note.
4. **Autopilot fails open during an AI outage (latent, autopilot is OFF)** - `legit_check.py:121` returns `legit:True ... "judge error, passed through"` on any Claude exception (also `:88` no key, `:91` unreadable thread), and `autopilot.py:165-169` trusts it; `autopilot.py:110-180` never checks `proposal["draftSource"]`, so a generic `template` draft (what `_ai_draft` returns when credits are out, `marcus_engine.py:951-964`) would be auto-sent if the operator runs `/autopilot on`. Fix: in `maybe_send`, skip unless `draftSource in ("claude","price_guard")` and `forge_heartbeat` AI is not hard-down; have the autopilot path treat legit errors as "not legit". Same check wanted in `ace.apply` before enabling ACE.
5. **Outbound page operates on the wrong Retell agent** - `retell_io.py:251` `agent_id = ags[0]["id"]` picks the first agent in the shared Retell account ("Restore & Construct Receptionist v3", roofing). `/api/outbound/agent` -> editable `generalPrompt`/`beginMessage` for that agent; `/api/outbound/calls` lists all account calls (barbershop, daycare, patient-screening); status agent list contains duplicates. Wholesale has no dedicated agent configured (`create_starter_agent`, `retell_io.py:335`, "Ava - Outbound Acquisitions" was never created). Fix: add `RETELL_WHOLESALE_AGENT_ID`, filter calls by that agent, dedupe by `agent_id`, refuse edits when unset.
6. **Rule-fallback mis-buckets while AI is down** (verified with `_rule_score`): "No, selling it to Diddy ..." and "Already sold it" -> warm/45 (pending tag approval for Alejandro Garcia is exactly this); "Offer?" and "You can text me an offer for consideration" -> warm/45 instead of hot (only "what's your offer"/"how much" hit PRICE); no "sold"/"other buyer" rule in `marcus_engine._HARD_NO_RE` (`marcus_engine.py:265`) or `seller_classify.py`. Fix: add sold / other-buyer / bare-"offer" patterns.
7. **Hot-lead queue has no aging** - 17 `asap` leads, newest seller message 2026-06-25 (one 08-03), still "Text back now" and on Do Today; nothing decays or demotes by age, so Speed-to-Lead and Mission Control "17 hot leads waiting on a call" overstate urgency. Fix: demote/flag asap after N days without movement (Scout reconcile pass).
8. **Test/demo data in live stores** - deals `uitest` ("Test Seller"), `flowtest`, voided contract "AUDIT-TEST (delete me)" show up in Deals/Buyers-dispo/Contracts and the `deals/stats` open value; `uitest` has a perpetual DocuSign 404 poll error. Clean via the UI/state files (not done here).
9. **Marcus status is optimistic** - `marcus_engine.py:1291-1296` hard-codes `"online": True`, `"hasAI": bool(key)`; ignores that the poll thread is not running and AI is down (row 6).
10. **Mission Control marks the wholesale card red for a daycare loop** - `mission_control.py:385-396`; by design but misleading on the REI card (wholesale loops are all green).
11. **Minor** - `/api/tasks` takes 8.7 s (100 sequential-ish GHL calls, `connector.py:788-812`) and only covers the 100 newest contacts; Conversations list has no paging past 100; `m_pipeline.jsx:2` comment claims desktop uses `/api/pipeline/move` (it doesn't); `/api/hub/roster?business=rei` returns empty (UI passes `wholesale`, so only a foot-gun for API callers).
