## Bugs found

1. **Deadlock in the Approval Center (severity high).** `agency_approvals_io.py:25` uses non-reentrant `threading.Lock`; `decide()` holds it (`:245`) while `_dispatch_approve(it)` (`:254`) runs. For kind `social` with no `METRICOOL_USER_TOKEN`, `agency_social.publish` calls `set_status(pid,"ready")` (`agency_social.py:346`) which calls `agency_approvals_io.add()` (`agency_social.py:310`) and blocks forever on the same lock. Reproduced with temp state: `decide` hangs and `list_queue` blocks afterwards. On the box this wedges Approvals, Dyson generate, Eco generate and Social until restart. Fix: in `publish()` skip `set_status` when the post is already `ready`, AND make the approvals lock an `RLock` (or dispatch outside the lock after a claim).
2. **Eco approve can never create an ad (high).** `agency_eco.py:615-628` builds `spec["account_id"]`, but `agency_ads._live_create_ad` requires `spec["ad_account_id"]` (`agency_ads.py:463`) and returns "spec.ad_account_id required". The spec also omits what `_live_create_ad` reads: `creative{message,link,headline}`, `page_id`, `budget_daily`, `targeting`, `objective` (headline/primary_text/cta are top-level keys nobody reads). The daycare path (`daycare_ads_studio.py:367`) builds the right spec. Fix: map Eco concept -> `ad_account_id`, `page_id`, `creative`, `budget_daily`, `targeting` (needs `geo_locations`), `objective`.
3. **`_live_create_ad` will likely be rejected by Meta (medium; unverified, cannot POST).** `agency_ads.py:489-499`: `optimization_goal=LEAD_GENERATION` with no `promoted_object {page_id}`, default targeting has no `geo_locations`, no `is_adset_budget_sharing_enabled`/bid fields, no image or link default. Also `_META_BASE` is Graph `v19.0` (`:93`), long past its 2-year window; bump to a current version.
4. **Live insights will lose ad/campaign identity (medium; needs a live test).** `agency_ads.py:196` requests `fields=spend,impressions,reach,clicks,ctr,cpc,actions,action_values,campaign_name,objective` but the parser reads `ad_id`, `ad_name`, `campaign_id` (`:238,254-255`). Add those to `fields` or every ad becomes "(ad)". Also no paging past `limit:100`; `purchase` only (no `omni_purchase`); leads = action `lead` only (website/pixel leads are `offsite_conversion.fb_pixel_lead`).
5. **Live account naming (medium).** `agency_ads.py:282` returns `clientName:""` for live data (Eco titles become "Eco: 3 new ad concepts — " and prompts say "Client context: ."). `accounts()` (`:405`) sets `clientName` = client id (e.g. `c2_1784159985755`). `analytics()` (`:427-428`) falls back to the demo id `act_1001` and queries Meta with it when a token exists but no map entry matches; `accounts()` (`:411`) returns demo accounts when a token is set without a map. Resolve names via `agency_io` and return an explicit "no account mapped" state.
6. **`agency_agents.status()` reports `online:true` and `connected:true` off key presence only (`agency_agents.py:365`)**, hiding the credit outage on the Agents tab. Wire to `forge_heartbeat.ai_health`.
7. **Eco approval payload lacks `dataSource` (low).** `agency_eco.py:519` payload is `{next, topAngle}`; mobile `MBADataNote` (`mobile/m_biz_agency.jsx`) therefore always prints "Ad data source not stated". Desktop Eco UI never surfaces `_source` (template vs Claude).
8. **Blueprint Studio stores a junk record per failed generate (low)** (`agency_build_studio.py:221-250`). Don't persist a record when `blueprint` is None (or dedupe by id).
9. **Shared sub-account (risk, by owner decision per memory).** Agency GHL == daycare location: agency tag sync, `billing/send` contact upsert/SMS/email, and dashboard KPIs all operate on the daycare's contacts and number. Consider at least a banner or a separate sub-account before onboarding a real client.
10. **`agency_ads.jsx` ~`:31-70`**: a *rejected* token shows "Meta Ads not connected, set META_ACCESS_TOKEN" (same as absent). The data already carries `source:"auth_error"`.
11. Stale docs: `agency_billing.py` header (separate agency Stripe account), `agency_eco.py` header ("(mock)" analytics), `AGENCY_DASHBOARD_FEATURES.md`.

Tests run (temp state only): `test_agency_lens` OK, `test_business_scope` OK, `test_eco_datasource` OK (makes a dummy-token call to Graph, harmless), `test_stripe_links` OK, `test_agency_messages` 15/15 OK, `agency_billing.py` / `agency_offers.py` self-checks OK. ## Meta ads: what it takes to go live

Current code path: `agency_ads.py` reads `META_ACCESS_TOKEN` and `META_AD_ACCOUNT_MAP` (JSON `{"<agency clientId>": "act_..."}`) from the process env (injected from `forge-agency/config/agency.env` by `_inject_env`; `META_` vars from other envs are intentionally isolated, so the daycare token cannot leak in). With a token it calls Graph `GET /{act}/insights` (level=ad, explicit time_range, retries 429/5xx), caches an auth rejection for 6h (`_AUTH_DEAD`), and falls back to labeled mock on any error. Creation = POST campaign -> adset -> adcreative -> ad, always PAUSED.

**Prerequisite for both options:** an agency (client) ad account must exist and be accessible. Today Pipeboard's single connection (Yahjair Mack, active) carries only the daycare account `act_1175564690150627`. Add the client's ad account to Yahjair's Business Manager (or have the client grant partner access), then re-run `get_ad_accounts` / reconnect at pipeboard.co/connections.

**(a) Fresh Meta system-user token (fits the existing code best)**
1. In Meta Business Settings, create a System User (Admin), assign the agency/client ad accounts (and the Page for creatives) with full control, generate a never-expiring token with `ads_read` + `ads_management` (+ `pages_read_engagement` for creatives) and a Meta app in Live mode.
2. Put `META_ACCESS_TOKEN=...` and `META_AD_ACCOUNT_MAP={"c2_...":"act_..."}` in `/opt/forge/forge-agency/config/agency.env` (deploy with `push.sh`, never git), restart `forge-reios`. Keep it separate from `daycare.env`.
3. Code fixes before trusting it: bugs 2-5 (spec keys, insights `fields`, client naming, bump `_META_BASE`), and add `page_id`/`promoted_object`/`geo_locations` for creation. Then the Ads/Eco pages flip from MOCK to LIVE automatically (`dataSource:"live"`), and approve creates PAUSED ads.
4. Smoke test read-only first: `GET /api/agency/ads?account=act_...`.

**(b) Pipeboard**
- Hosted Meta Ads MCP: `https://mcp.pipeboard.co/meta-ads-mcp` (also `https://meta-ads.mcp.pipeboard.co/`), auth `Authorization: Bearer <PIPEBOARD_API_TOKEN>` (query `?token=` works but leaks into logs). It is JSON-RPC over HTTP (`tools/call` with `get_insights`, `get_campaigns`, `get_ads`, `create_campaign`, `bulk_create_ads`, ...), not a plain REST API. Sources: github.com/pipeboard-co/meta-ads-mcp, pipeboard.co/guides/meta-ads-mcp-server.
- `PIPEBOARD_API_TOKEN` currently lives only in the Mac `~/.agents.env`; the box has no Pipeboard var. Needs adding to the box env via `push.sh` (secret), plus a new ~60-line stdlib JSON-RPC client in `agency_ads.py` (`initialize` + `tools/call`) that returns the same shape as `_live_analytics`. Per-account calls auto-route to the owning Facebook login, so no per-account token is needed.
- Pros: no app review/system-user work, Pipeboard handles token refresh and Graph versioning. Cons: third-party dependency and quota/plan limit, extra hop, and the OAuth connection is tied to a personal Facebook login that expires ("expired" requires manual reconnect).

**Recommendation:** (a) for the box (no third party, matches existing tested code paths and the daycare's eventual needs); keep Pipeboard for interactive Claude sessions (e.g. the enrollment-ad runbook). Either way the agency ad account is the real blocker, not the code.
