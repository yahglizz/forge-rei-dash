### Logic details
- Agent-name routing (Parse nodes): regex `^[\/@]?(marcus|scout|atlas|dyson|eco|solomon|orion)\b[:,]?\s*` case-insens. on the text. Hit -> agent=that name, message=text with the prefix cut. No hit -> agent='orion', message=whole text. Empty message -> default "Say hi and tell me what you can do from here."
- Output of Parse = `{ chatId, route:'chat', body:{ agent, message, sender_id, idempotency_key } }`.
  - Telegram: sender_id = String(message.from.id); idempotency_key = 'tg-' + update_id. chatId = message.chat.id (kept for the reply).
  - Chat page: sender_id = hard-coded literal (owner's Telegram id); idempotency_key = 'page-' + $execution.id; no chatId.
- Owner-only check: there is NO IF/guard node. Telegram lane: the Telegram Trigger's `additionalFields.userIds` filter compares the sender's Telegram user id to one hard-coded owner id, trigger-side, so non-owner messages never start a run. Chat page lane: n8nUserAuth (must be logged in as an n8n user); sender_id is then hard-coded to the owner id. The box gateway also receives sender_id; whether the box re-checks it against an allowlist = Unknown (not visible in n8n).
- Call to Dispatch: Execute Workflow node passes the Parse item straight through (Dispatch trigger uses inputSource=passthrough). Waits for the sub-workflow, so the whole chat runs inside one parent execution.
- Reply formatting:
  - Telegram: status 'failed' -> "That did not run: <error>"; else reply (or "No answer came back."). If status 'needs_approval' append "Waiting on your tap in the business chat." Strips `**`, HTML-escapes & < >, slices to 3900 chars, sends parse_mode=HTML.
  - Chat page: same text rules, appends "Waiting on your tap in the business Telegram chat." No escaping/slice.
- Tap-card handling: Agent Chat does NOT render or forward `cards`. Dispatch returns `cards`, but the Format nodes only look at status/reply/error. On needs_approval the user is told to tap in the business chat; the tap card itself is posted by the box (per-business Telegram chat). Where a Slack-originated tap card would land = Unknown (box-side).
- Credentials used (names): FORGE Agent Bot (telegramApi) only.

## 2. FORGE Agent Dispatch (id XNvR287qpWUR6xPk) ACTIVE, 13 nodes, 0 own triggers
Sub-workflow. Trigger node "From Caller" = executeWorkflowTrigger @1.3, inputSource=passthrough. Description says it is called by every workflow that runs an agent.

### Input contract
Item JSON: `{ route: 'chat'|'run' (anything not 'chat' becomes 'run'), body: {...} }`.
- body.idempotency_key is REQUIRED (Set Up Job throws without it).
- For route=chat, body seen from Agent Chat: `agent`, `message`, `sender_id`, `idempotency_key`. Other body fields for route=run = Unknown (not exercised by Agent Chat).
- Set Up Job adds `deadline = now + 6 min`.

### Flow
From Caller -> Set Up Job (code) -> Owner Chat Start? (IF route==chat)
- true -> Start Owner Chat (httpRequest @4.5): POST https://forge-reios.tail0a2dda.ts.net:8443/gateway/v1/chat, JSON body = Set Up Job body, timeout 20 s, fullResponse, neverError, onError continueRegularOutput. cred httpHeaderAuth "FORGE Gateway Owner Key" (id Hfi3XKMNR6QcD8HB).
- false -> Start Workflow Job (httpRequest @4.5): POST .../gateway/v1/run, same options. cred httpHeaderAuth "FORGE Gateway Workflow Key" (id 6wNmTszQtZKdX758).
Both -> Read Reply (code) -> Finished? (IF next==finish)
- true -> Return Result (noOp) = output.
- false -> Wait Before Next Try (wait @1.1, `$json.wait` seconds) -> Start Again? (IF next==start)
  - true -> back to Owner Chat Start? (re-POST)
  - false -> Owner Chat Poll? (IF route==chat) -> Poll Owner Chat (GET .../gateway/v1/jobs/{jobId}, Owner Key) or Poll Workflow Job (same URL, Workflow Key) -> back to Read Reply.

### Read Reply decision table
- body.status in done|needs_approval|failed -> finish.
- past deadline (6 min) -> finish failed "Timed out waiting for the box...".
- no HTTP status code: no jobId -> finish failed "Box unreachable"; else poll (wait 15 s).
- HTTP 429/503 -> re-start (wait 30 s).
- status 'lost' -> re-start (wait 5 s), second time (attempts>=2) -> failed "Job was lost twice".
- HTTP >=400 -> failed "Gateway said <code>".
- else poll (wait 10 s). Gateway job id read from response `id`.

### Output contract (item from Return Result)
`{ next:'finish', jobId, status ('done'|'needs_approval'|'failed'), error, agent, task, reply, cards[], done[], checks|null, receipts|null, attempts }`.

Auth: two httpHeaderAuth creds, header name/value hidden (secrets not read). Owner Key used for /chat + its poll; Workflow Key for /run + its poll.

### Slack-side steps (Unverified, standard Slack setup; confirm in Slack UI)
1. api.slack.com/apps -> the app (use the bot behind 'FORGE Slack Agents Bot' if that is the agents app; which app each cred points to = Unknown).
2. OAuth & Permissions -> Bot scopes: `chat:write`, `im:history`, `im:read` (+ `users:read` if resolveIds). Reinstall app after scope change.
3. App Home -> turn on "Messages Tab" and "Allow users to send ... messages from the messages tab" (else users cannot DM the bot).
4. Event Subscriptions -> Enable -> Request URL = the trigger node's Production URL. Slack POSTs a `url_verification` challenge; n8n's Slack Trigger answers it (Unverified), so URL must be active/published first.
5. Subscribe to bot events: `message.im` (DM). Add `app_mention` only if channel use wanted.
6. Save, reinstall if prompted.
A Slack app has ONE Request URL. So one app = one Slack Trigger node. A second workflow wanting events from the same app cannot have its own URL; route inside one workflow instead.
Slack retries events when no 200 in 3 s (header X-Slack-Retry-Num). n8n Slack Trigger responds immediately (Unverified); use the event id / client_msg_id / ts as idempotency_key so retries do not double-run.
Bot's own replies in the DM also fire `message.im` (with bot_id). Each one starts an execution unless filtered trigger-side (`options.userIds` may filter before execution like the Telegram userIds filter = Unverified). Otherwise they count against the budget.
